# 김영훈 작업 순서와 진행 상태

기준: 2026-10-20, 대학 과제용 SubMate. 기본 브랜치 develop의 회원/JWT·상품·거래 코드를 유지하고 `codex/jwt-frontend-integration`에서 공통 Frontend 연결을 진행합니다.

## 확정 담당

- 김현빈: 회원·JWT·상품·카테고리, 강의 목록/상세, 강의·차시 콘텐츠 관리.
- 김영훈: 구독·결제·환불, 수강 권한, 학습 진도, 내 학습·이어 학습, 수강 화면 연결, 공통 UI, ERD/API 검토, 통합 테스트.

## 이번 연결의 경계

회원/JWT·상품 Backend, SecurityConfig, SQL과 거래 정책은 수정하지 않습니다. 상품 선택 화면은 기존 상품 API에서 결제 페이지로 연결하는 조회 전용 연결 화면입니다. 정식 상품 상세·관리와 강의 관리 기능을 대체하지 않습니다.

실제 로그인은 POST /api/auth/login의 `token`을 받으며 GET /api/auth/me에서 memberId/email/role을 확인합니다. App 세션은 기존 accessToken/email/role 규약을 유지합니다. 토큰·인증 정보는 메모리에서만 보관하고 새로고침 시 다시 로그인합니다.

기존 Backend의 업무 오류 중 일부도 401이므로, 보호 API의 401에서 /auth/me를 확인하고 실제 인증 실패일 때만 세션을 종료합니다. 잘못된 로그인은 로그인 화면에서 안내합니다. 이 처리가 Backend 오류 코드 수정 자체를 대신하지는 않습니다.

## 현빈님과 맞출 항목

- 실제 MySQL 신규 설치/기존 DB 갱신 순서와 부모 테이블 계약.
- 회원·카테고리 예외 응답 수정·패키지 정리 현황.
- 강의/차시 API 경로·응답, 상품에 포함되는 강의 관계.
- 차시 공개·학습 완료·이용권 구성 변경과 기존 수강자 영향.

강의 API가 없는 상태에서 가짜 강의나 임시 진도 API를 실제 기능처럼 추가하지 않습니다. 운영용 Refresh Token·토큰 블랙리스트·영상 스트리밍 인프라는 현재 과제의 필수 범위에 넣지 않습니다.

## 이번 검증 결과

실제 MySQL 대신 별도 H2 메모리 DB와 일반 JWT Security로 확인했습니다.

- 브라우저: 공개 상품·판매 중지 → 비회원 구독 신청 → 회원가입 → 잘못된 로그인 안내 → 정상 로그인 → 원래 결제 화면 복귀 → 가상 결제 → 구독 상세 → 해지 후 잔여 이용 → 환불 요청·내역 → 로그아웃 → 재로그인 재조회 → 새로고침 인증 초기화.
- 별도 API: 다른 회원의 구독·환불 0건, 타인 구독 404, 일반 회원의 관리자 결제 조회 403.
- 자동 검사: Frontend 인증 헤더/가입 payload/본인 정보/로그아웃/복귀 경로 테스트 5건, build/lint, 스타일 토큰 참조.
- 관리자 환불 승인/반려의 실제 JWT 브라우저 경로, 토큰 자연 만료까지의 실시간 대기, 실제 MySQL, 모바일 기기별 검사는 미수행입니다. 이 기능까지 모두 새로 검증했다고 간주하지 않습니다.
- 기존 Backend 27건 통과는 같은 세션에서 확인한 기존 검사 결과입니다. 이번 구현은 Backend 소스 변경 없이 진행했습니다.

작업 중 사용자가 별도로 변경한 Backend 들여쓰기와 output 문서 삭제는 보존했습니다. 빠진 React Router 의존성은 사용자 확인 후 원래 버전으로 복구했습니다.
